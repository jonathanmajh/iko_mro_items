# EAM Spare Parts

**GUI tool for validating item descriptions**

Based on the minimal Electron application based on the [Quick Start Guide](https://electronjs.org/docs/tutorial/quick-start) within the Electron documentation.

## To Use

To clone and run this repository you'll need [Git](https://git-scm.com) and [Node.js](https://nodejs.org/en/download/) (which comes with [npm](http://npmjs.com)) installed on your computer. From your command line:

```bash
# Clone this repository
git clone https://github.com/jonathanmajh/iko_mro_items.git
# Go into the repository
cd iko_mro_items
# Install dependencies
npm install
# Run the app
npm start
npm run make
```
Note: This app reads and writes Excel (`.xls`/`.xlsx`/`.xlsm`/`.xlsb`), Maximo import spreadsheets, and SQLite databases (`better-sqlite3`). Native modules such as `better-sqlite3` are rebuilt for Electron automatically by the Forge toolchain, so use `npm install` then `npm run make` (do not open the HTML files directly in a browser).

Using
```
node v24.18.1
npm 11.x
electron v41.0.3
better-sqlite3 v12.8.0
electron-squirrel-startup v1.0.1
exceljs v4.4.0
```

Publishing: Electron Forge (`@electron-forge/publisher-github`) creates builds and releases from tags.
```
npm run make          # build distributables
git push --follow-tags
npx npm-check-updates (-u)   # check for dependency updates
```

## Development notes

### Environment config (`.env`)
Copy `.env.example` to `.env` for local overrides (Maximo host, DevTools, Firebase keys) instead of exporting variables in every shell. `.env.local` optionally overrides `.env` per machine. Precedence: real environment > `.env.local` > `.env` > production defaults in `assets/constants.js`. Both files are gitignored; production builds are unaffected (no such files exist inside the packaged app).

### Updating vendored Bootstrap
The app uses two committed files, `renderer/vendor-bootstrap.bundle.min.js` + `renderer/vendor-bootstrap.min.css` — the `bootstrap` npm package is a devDependency (version tracker only) and is pruned from the installer. To upgrade:
```
npm install -D bootstrap@<new-version>
npm run vendor:bootstrap
```
Review the diff of the two vendor files, then commit them.

### Firebase bundle
The packaged app does not ship the Firebase SDK. `assets/firestore.js` loads `assets/firestore.bundle.cjs`, a tree-shaken esbuild bundle regenerated by `npm run build:firestore`, which runs automatically on `postinstall`/`prepackage`/`premake`. Run it manually only if you edit `assets/firestore.sdk.js` and want to test the bundle without reinstalling.

### Packaging (`forge.config.js`)
- `asar` is enabled: **never write files next to app code** — `__dirname` inside `app.asar` is read-only. Use `app.getPath('temp')` / `app.getPath('userData')` (see the `write-file` handler in `main.js`).
- The installer excludes `assets/program.db` (gitignored; fresh installs recreate the schema and sync via `remotedb.js`), all `*.map` files, tests/docs, and Chromium locales except `en-US`.
- `npm run package` for a quick local packaging check, `npm run make` for the Squirrel `Setup.exe` in `out/make`.

### Tests & lint
```
npm test        # vitest
npm run lint    # eslint (warnings ok, errors fail CI)
```
If DB-backed tests fail with a `NODE_MODULE_VERSION` mismatch, the `better-sqlite3` native module was last rebuilt for Electron (Forge does this at package time). Rebuild it for your system Node with `npm rebuild better-sqlite3` (or a fresh `npm install`).

## To edit
### Editing CSS:
When linking css to an html file, use style.css as the only stylesheet. If you make another stylesheet, import it into style.css.
### Live editing:
Use ```npm start``` to open the application (make sure you've installed all dependencies using ```npm install``` at least once). Once you make any changes, hit ```ctrl+r``` in the app to refresh the page. To restart the app, enter ```rs``` in the terminal. Opening the html file in a browser directly will prevent the JS from loading.
